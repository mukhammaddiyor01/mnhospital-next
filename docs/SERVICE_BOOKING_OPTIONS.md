# Service detail booking options

The Standard option is the base catalog service. Additional options are explicit packages linking that base to one to three active additional services from the same doctor and room. An unrelated service with the same category is not a package.

Admins manage these in Services → Booking options. Selecting included services fills a suggested combined title and total duration. Admin enters the full discounted package price, reviews it and publishes the initially inactive real service. The existing doctor/category limit of four services still applies. General service creation remains doctor-only.

Patients see composition, full time, separate purchase total, package price and savings. Selecting the native radio control updates the summary and sends the chosen real service to the existing appointment calendar and cash/Eximbay flow. Server-owned booking snapshots remain authoritative. Component availability is intersected and changed component prices cannot create misleading discounts for new bookings.

Legacy standalone options require explicit admin configuration; prices in screenshots and disposable verification are examples only. See [clinical workflow verification](CLINICAL_REPORTS_AND_PACKAGES.md).

# Service detail booking options

The selector reuses existing service records, rather than inventing prices or introducing a parallel package/payment model. The current active service is the Standard choice. Alternatives must share the same doctor, department and service type, have an active doctor and service, and a finite nonnegative price. Duplicates are excluded. A blocked or unavailable base service cannot enable the selector through a cached alternative.

Doctors create alternatives through their existing Services workspace: create another service with its own name/title, price, whole-minute duration and calendar, using the same department/type. The existing backend limit of four services per doctor/type remains unchanged. Alternatives appear automatically on each matching detail page. If only one service exists, only Standard appears. Preview catalog entries never enable booking.

Selecting a radio choice updates its price summary and booking link. The chosen real service ID goes to `/appointment?service=...`; the appointment page fetches that service directly even outside the first 50 catalog entries. Each alternative therefore uses its own availabilityDates, doctor schedule, duration and available slots. The patient selects a date/time and continues to the existing cash or Eximbay test checkout. Checkout still derives and snapshots the price on the server; the browser cannot submit an invented price or duration. No payment, role, authorization or database schema changes were made.

The selector uses native radio controls, keyboard focus, live selection summary, EN/KR/UZ copy and existing light/dark theme tokens. Failed alternative queries retain the valid Standard option with a retry control. A changed/removed choice falls back to the current valid service.

Verification: `node scripts/verify-service-booking-options.cjs` (32 checks); `node scripts/verify-api-contract.cjs ../mnhospital http://127.0.0.1:2001/graphql` (108 contracts, zero errors); production frontend build; browser confirmation that the detail booking link selects the same real service and price on the appointment page. At verification time, the live catalog contained five public services with no same-doctor/department/type alternative groups, so it correctly displayed Standard only. Multiple choices and rejection of mismatched/inactive entries were checked with artificial fixtures, without adding medical catalog records.

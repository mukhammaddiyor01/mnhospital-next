# Unread notification and message indicators

The signed-in patient header has dedicated Messages and Notifications links. Staff topbars and sidebar links show the same unread counts, and patient profile action cards reuse them. Counts appear as a small red badge, hide at zero and display 99+ above 99. Accessible names include the actual count and the existing EN/KR/UZ unread label. The Guest chat launcher stays separate from the private inbox.

getMyUnreadNotificationCount scopes UNREAD records to the verified receiver ID plus role. getMyUnreadMessageCount first selects authorized DIRECT conversation IDs and counts incoming unread, non-deleted messages. Sender role and ID are both compared so equal IDs in different profile collections cannot be confused. Counts are not limited by inbox pagination and expose no message content.

A single account-keyed UnreadProvider shares counts across the UI. Authorized privateMessage/privateRead socket events refresh counters, and visible-tab polling/focus refresh covers missed events and ordinary notifications every 10 seconds. Account changes remount the provider, close its socket and use the existing expectedAccount request guard. Count failures preserve the last valid same-account result.

Reading a private conversation clears only its existing MESSAGE/CONVERSATION notifications for that receiver. Newer arrivals, other conversations and clinical alerts are untouched. Message persistence and the notification attempt finish before the private message event is published. Hidden tabs cannot automatically mark newly received messages read; visible selected conversations reconcile unread incoming messages on return. Notification Details/Open, Mark read, Archive and Mark all read refresh indicators. Marking all notifications read does not read private messages.
